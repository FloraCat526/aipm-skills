# Product Frameworks

## JTBD

Use when clarifying user motivation.

Prompt:

When [situation], the user wants to [motivation/job], so they can [desired outcome].

Ask:

- What triggers the need?
- What progress is the user trying to make?
- What alternatives do they use now?
- What makes the job hard?
- What outcome would make them switch?

## User Journey

Use when analyzing end-to-end experience.

Stages:

- Awareness / trigger.
- Setup.
- First action.
- Core task.
- Review and correction.
- Completion.
- Repeat use.

For each stage capture actions, pain points, emotions, product opportunities, and metrics.

## Kano

Use when classifying features by user satisfaction.

Categories:

- Basic needs.
- Performance needs.
- Excitement needs.
- Indifferent.
- Reverse.

Avoid scoring without user evidence. Use as a hypothesis map if research is missing.

## RICE

Use for prioritizing roadmap items when estimates are available.

Formula: `Reach * Impact * Confidence / Effort`.

Do not fabricate scores. Ask for estimates or use qualitative `高/中/低` with `待确认`.

## ICE

Use for early prioritization when speed matters.

Formula: `Impact * Confidence * Ease`.

Best for experiments and growth ideas, not high-stakes roadmap commitments.

## MoSCoW

Use for MVP scope.

Categories:

- Must have.
- Should have.
- Could have.
- Won't have now.

Make "Must have" strict: if everything is must-have, the framework has failed.
